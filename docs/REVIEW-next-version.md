# 对《Goban 下个版本产品评审》的复核与补充

复核日期：2026-09-05。基准 main `bef97c0`（v1.62.0）。本文件是对外部评审报告的逐条核对，加上报告没有覆盖、但决定"下一版是否质变"的补充项。方法：读 src/web/js 源码、跑 `node scripts/test-game.mjs`（all passed）；没有跑浏览器流程，没有做棋力实测。

## 一、对报告的总体判断

报告质量高：定位清楚（"每下一局，学会一个自己用得上的判断"），发现有代码位置、有验收条件，并且分清了"代码可确认"与"没测到不能断言"。建议**采纳它的定位和 A/B/C 切分**作为下一版主线。

但有三点需要修正或补强，否则按报告执行会做出"功能更多、体验未质变"的一版：

1. **报告低估了"素材断供"问题。** 练习题只从当前对局 + 手动存档槽派生（app.js:1918）；统计只记计数不记手顺（stats.js:121）。一局下完不存档，这局的失着就永远无法变成题。报告 P1-4 建议的"终局 → 练关键手 → 回原局"，前提是终局对局被自动留存，这件事应当排到 A 段而不是 B 段。
2. **报告把"分析证据分层"当成 UI 标注问题，实际它是评估器问题。** review.js 里失着有两类：coachFacts 的硬判定（一步成五/漏防，规则正确）和静态分差 ≥ 0.45 的启发式。给后者贴"待确认"标签只是诚实，不是质变。质变的做法是把启发式失着交给引擎做一次**反事实搜索**（实际着 vs 引擎最佳着，同一局面同一预算），这条通路已经存在（app.js:387 的 scheduleAnalysis 用 600ms 引擎给"更优点"），缺的是把它接进整局复盘并缓存结果。
3. **报告没有提到棋力本身。** ROADMAP 已把"2.0 三步"写明：① 规则核心（已做）→ ② 引擎知禁手（做了一半：出口合法化，搜索内部仍按自由式）→ ③ 定价与调平（未做）。一个以"学习"为定位的产品，教练的判断可信度上限就是引擎的棋力。② 的后半（白方利用禁手点、黑方搜索内避开禁手）与 ③ 应当有自己的版本位置。

## 三、报告没有覆盖、但影响质变的项目

按"对目标玩家可感知的差别"排序。

### 1. 对局自动留存与"本局档案"（应进 A 段）

现状：一局结束只剩计数。没有 history 的统计，无法回看、无法出题、无法做"次日复测"。

下一版：每局终局自动写入本地对局库（history、ruleSet、mode、difficulty、humanColor、endedAt、result、时长），存档槽保留为"命名收藏"。对局库是复盘、出题、间隔复习三条线共同的数据源。容量以 N 局滚动，用户可导出为 SGF 集合。

验收：不点存档，下完一局关掉再开，仍能从"最近对局"打开复盘并生成本局练习题；统计与对局库条数一致。

### 2. 引擎反事实评估进入整局复盘（A 段，与"证据分层"合并）

现状：整局复盘只跑静态评估（review.js:68），引擎只在逐手浏览时以 600ms 预算给"更优点"（app.js:387）。

下一版：整局复盘分两遍。第一遍静态，立即出曲线；第二遍后台对每个候选失着做引擎比较（实际着 vs 最佳着，可取消、可恢复、有进度），完成后把失着列表按证据升级为"可证明战术 / 引擎比较 / 静态波动"。禁手档下曲线偏乐观的已知偏差（README 记录 3.5%）由此被引擎比较部分修正。

验收：曲线仍秒出；后台分析可中断且中断后不留半成品；同一失着在"引擎比较"档展示两条着法序列，可一键在推演模式中落入对比。

### 3. 引擎 2.0 第 ②③ 步排入版本（不可从产品线剥离）

现状（ROADMAP v1.55）：搜索内部按自由式算，交货口验一次；白方不利用禁手点；C2 自战黑方显著占优（自由式黑 19 白 5，禁手档黑 10 白 2）。

下一版至少做：搜索内候选生成对黑方过滤禁手点（ROADMAP 已测过全量判定成本过高，但"只在冲四/活三生成点判一次"的增量方案未测）；白方评估把"逼黑入禁手"计入。调平（③）可以后一版。

验收：现有 `scripts/test-strength.mjs` 与 `arena.mjs` 加禁手档配对局；黑方在禁手档下的首选点是禁手点的比例从 3.5% 降到 0；交货口兜底触发次数从"每 41–45 手一次"降到零或接近零。

### 4. 难度重新定义为"对手画像"，并给出可校准的承诺（升到 P1）

现状：简/普/难/极四档，难与极靠思考秒数区分，"简单"只是随机化。

下一版：每档写一句面向玩家的承诺并用固定局面集验证。例如：入门"会漏挡活三，但不会漏挡冲四"；普通"必挡直接威胁，不主动做杀"；困难"会做 VCF"；极限"给定预算下最强"。校准脚本用 bench-tiers.mjs 扩展：对每档跑固定局面集，断言承诺成立（如入门档在"必须挡冲四"局面上 100% 挡住，在"活三"局面上有可观漏挡率）。

验收：每档承诺可被脚本证伪；README 难度行改为写承诺，不写引擎实现。

### 5. 终局总结与"重下关键一手"（B 段核心，同意报告）

补充两条实现细节：

- 终局后不弹层，改为侧栏顶部出现总结卡，棋盘保持可见；卡内三个动作：重下关键一手、看复盘、再来一局。
- "重下关键一手"实质是把当前局面回退到关键手前、锁定为练习态（对手由引擎按原规则应手）；成功或失败后回到原局，原 history 不被改写。这与现有推演模式（app.js:1073 variationCells）共用机制，但需要把推演从"只读虚影"变成"可落子的分支"。

### 6. SGF 变着与推演持久化（B 段，与 5 联动）

现状：parseSgf 只取主线（sgf.js:94 extractMainline），推演结果不保存。

下一版：复盘中的替代着序列作为变着写入 SGF，导入时保留第一层变着并可切换。这是"复盘 → 重试 → 保留"闭环的存储形态；没有它，用户练完的东西在关闭后消失。

### 7. 题目身份对称归一（C 段前置，小改动）

puzzleKey 对 8 种对称取最小字符串后再哈希。这一条要在引入间隔复习之前做，否则复习记录会被同题的镜像分裂。

### 8. 训练回访机制（C 段，同意报告，补数据模型）

进度对象从 `{n, wrong, ok, last}` 扩到 `{n, wrong, solo, hinted, revealed, due, interval}`。掌握 = 无提示独立答对且到期复测再答对。每日挑战改为从 due 队列里取，不足才从题库补。这样"每日"从随机 5 题变成有意义的复习。

### 9. 棋盘键盘与读屏可达（可拆到任意版本）

方向键移动焦点交叉点、Enter 落子、Esc 取消；焦点点用与提示不同的形状；状态区播报"H8 空 / 已占 / 禁手：双三"。棋盘 canvas 加 role=application 并维护 aria-activedescendant 到一个隐藏的 225 项列表。禁手原因文案已存在（renju.blocked.*），只是没人播报。

### 10. 不建议本版投入

同意报告：联网、账户、排行、订阅、泛化聊天教练不做。补充两条也不做：更多主题（四套已够，改动点在右栏内容）；把 C1 引擎删掉（简/普档需要它的随机性与低预算表现）。

## 四、建议的版本顺序（修订报告的 A/B/C）

| 段 | 内容 | 为什么先做 |
|---|---|---|
| A 可信基础 | 对局自动留存 · RU 读写与规则贯通 · 练习继承规则 · 题目对称去重 · 引擎反事实复盘 | 后面所有学习功能都读这些数据；引擎比较是"解释"的证据来源 |
| B 主体验 | 常驻复盘面板 · 终局总结卡 · 重下关键一手 · 变着保存 · 难度承诺与校准 | 用户可感知的质变发生在这一段 |
| C 学习回访 | 分层提示 · 掌握模型 · 间隔复习 · 每日改为到期队列 | 依赖 A 的数据与 B 的入口 |
| D 引擎 2.0 ②③ | 搜索内禁手 · 白方利用禁手 · 先后手调平 | 独立可发布、可回退，但不能无限期后延 |

垂直切片（与报告一致，加一条前提）：**不存档**输掉一局 → 终局卡指出一次可证明漏防 → 不看答案重下 → 引擎展示对手惩罚 → 次日"每日"里再次遇到同题并独立答对。
