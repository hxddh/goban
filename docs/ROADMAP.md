# Goban 路线图 — v1.30.0(本版) · 后续评估

> 评估基准:v1.29.0(中英双语)。
> 已具备:C1/C2 双引擎、复盘 3.0、swap2 平衡开局、战术练习(三题型 + 错题本)、
> 每日挑战、对局统计、四套棋盘主题、SGF 全链路、多存档槽、中英双语、
> macOS/Windows 双平台发布。

## v1.30.0 · 本版内容

题库扩容 + 把「发布出去才走的那条路」纳入测试 + 应用内版本号。

- **题库 53 → 120+**。每日 5 题下,53 道 46 天见底、与前一天重复 0.47 题/天;
  扩容后见底天数与重复率都改善一倍以上。生成器开局集同时放宽(5×5 网格 × 三种起手),
  因为旧开局集把 vcf 目标抬到 40 也只挖得出 13 道就扫完了。
- **打包版 worker 路径上闸**。`js/worker-src.js` 是构建时生成的,源码目录没有,于是测试
  一直 404 它、走 fetch 兜底;而装机版只能走内嵌那条。清单还被抄了两遍。现在生成器从
  `engine.js` 读清单,单测按 Worker 方式启动真实 bundle,交叉回归改跑打包路径并新增一例。
- **应用内版本号**。说明弹层显示版本,与棋谱印章、安装包同源(`version.js`),单测锁到 `app.zon`。
- CI 增加 Windows 单测作业;存档改名失败不再静默;练习进度存储加 2000 条上限(先丢「做对且
  从没错过」的,错题本最后动)。

## 后续候选(未排期)

| 项 | 说明 | 证据 |
|----|------|------|
| vcf 题量 | 扩开局集后仍是最难产的类型;要再往上需要换采集策略,而不是继续加开局 | 已实测 |
| 练习难度分级 | vcf 有真实梯度(深度 3–8);win1/defend 的解数几乎全是 1,只剩子数一个维度,分级会沦为按子数排序 | 已实测 53 题全量 |
| 棋盘键盘可操作 | canvas 无 tabindex、不在 Tab 环内,三条键盘路径均无法落子;弹层 a11y 早在 v1.25.2 就做过,前后不一致 | 已实测(本版明确不做) |
| Windows exe 版本资源 | 应用内版本号解决的是前端侧;exe 自身仍无版本资源,属 zig/打包侧 | 已实测 |
| 英文文案润色 | 翻译以准确为先,可再按母语习惯打磨(尤其帮助表与教练评语) | — |

注:「检查更新」与当前安全姿态冲突(`.permissions = .{}`、外链 deny、导航白名单
只有 `zero://app`),要做需单独决策。

## 明确不做

| 项 | 原因 |
|----|------|
| 用户对局出 VCF 题 | 实测 11 局 283 个局面(两档强度),可出题的漏招 **0** —— 能走 VCF 时要么已被 win1 覆盖、要么走的人自己就找到了。成本不是问题,产出才是。要做须先拿真实用户棋谱验证产出率 |
| 计时对局 | 横切面大,仍无明确需求 |
| 禁手规则(Renju) | 动 core + 双引擎,需先 spike |
| 联机对战 | 超出纯前端 + zig 壳量级 |
| Linux 打包 / 自动更新 | 平台侧,自动更新与联网决策绑定 |

## 验收口径

- 单测全绿(含 i18n 四道闸、worker bundle 闸、版本号闸);交叉回归 10/10;每日/练习 8/8;强度基线不变。
- 涉及文案的改动:英文态全控件命中/溢出审计必须干净。
- 引擎类改动:`scripts/arena.mjs` 相对上一个发布 tag 净分为正,且换一档预算复现。
- 题库类改动:`打开练习` 延迟必须留在百毫秒量级(v1.27 从 3.3s 压到 66ms,不可回退)。
