## v1.26.0 · 评估

### P0 · 计时对局(主菜,按 1.25 路线图的既定排期)

1.25 明确把计时对局移出并指定「作为 1.26 的主菜单独做、单独回归」,理由是
横切面大:**时钟 × 悔棋 × 存档/恢复 × 导入续下 × swap2 × AI 思考预算**,
正是 v1.23.1 花整版清理的那类交叉场景。单独成版可以给足回归空间。

建议范围(先窄后宽):
- 每方**总时限**制(如 5 / 10 / 20 分钟,默认关闭),超时判负;
  不做读秒/加秒制,留给后续版本按反馈决定。
- 时钟入存档与 SGF 导出注释;恢复/续下时从存档时刻继续计时。
- 悔棋、复盘浏览时的走停规则明确定义并入交叉回归
  (test-cross.mjs 新增时钟 × 各场景组合项)。
- AI 侧只读时钟不改预算:极难档的 5–8 秒思考在短时限下的表现
  需在验收中明确(AI 超时同样判负,属规则一致性)。
- 引擎与 core 胜负判定不动;超时判负在对局流程层(app.js/state.js)实现。

风险:中。不碰引擎,但碰对局主流程,需要整版的交叉回归投入——这正是
把它单独成版的原因。

### 明确不入 1.26(沿用 1.25 的评估,情况未变)

| 项 | 原因 |
|----|------|
| 禁手规则(Renju) | 动 core 规则层 + 两个引擎胜形判定,回归风险最高;立项前需先做引擎侧可行性 spike |
| 联机对战 | 需要服务端/信令,超出「纯前端 + zig 壳」一个量级,单独立项评估 |
| 英文界面 i18n | UI 稳定后一次性抽取文案;计时对局会新增文案,做完再抽更省 |
| 开局库浏览器 | 受众窄,继续观察 swap2 使用反馈 |
| Linux 打包 / 自动更新 | 平台侧改动,与打包侧其他改动一并评估 |

## 验收口径(1.26)

- 单测全绿;时钟状态机(走/停/超时/跨存档恢复)入单测。
- 交叉回归扩展:时钟 × swap2 / 悔棋 / 存档恢复 / 导入续下 全组合,0 控制台报错。
- 引擎强度基线不变(`test-strength.mjs`);AI 不因时钟改变思考预算。
