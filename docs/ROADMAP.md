## v1.31.0 · 本版内容

三项都是已发布功能的实测缺陷,不是新功能。

- **电脑不再每盘下同一局**。同一开局重复 8 局,困难档只走出 1 盘棋(普通 3 盘);
  真机预算下同一局面连测 5 次应手逐字相同。改法不是「在分数接近的着法里挑」——那是拿棋力
  换花样——而是**用局面已有的对称性**取等价着法:棋盘翻转后局面不变,翻转后的应手就是同一手
  棋换个镜像坐标。困难 1 → 5 盘不同,普通 3 → 6;arena 对 v1.30.0 净 0,强度基线不变。
- **复盘曲线原本是贴顶的平线**。`tanh(raw/1200)` 在第 7 手就恒等 1.000000,91 手里 90 手的
  逐手跌幅恰好为 0;失着判据一次都没触发,每局只报「输掉的那一手」。曲线改对数压缩(活三读
  0.60 而非 0.97),判据改为「对手应手之后」再比。每局失着 1 → 平均 4.5 处,首个比终局提前
  中位 21 手,上限 8 处。
- **全部数据可备份**。六个存储键一次导出为 JSON,恢复前校验 + 确认,整体替换。此前只有棋谱
  导出(一次一局),统计/打卡/练习进度完全没有出口。

## 后续候选(未排期)

| 项 | 说明 | 证据 |
|----|------|------|
| 变化性再往前 | 对称性只在局面对称时有轨道,通常是开局几手。再往后要变化就得动「接近最优」,那是真实棋力代价,需先用 arena 定价 | 已实测 |
| 失着判据 | 现为静态评估跌幅 + 两条硬判据。更准的转折点(允许对手成活四/双三)需要新的判据并重新定阈值;我试过的 VCF 判据在样本里 0 命中 | 已实测 |
| vcf 题量 | 扩开局集后仍是最难产的类型;再往上需要换采集策略 | 已实测 |
| 练习难度分级 | vcf 有真实梯度(深度 3–8);win1/defend 的解数几乎全是 1,分级会沦为按子数排序 | 已实测 130 题全量 |
| 棋盘键盘可操作 | canvas 无 tabindex、不在 Tab 环内,三条键盘路径均无法落子 | 已实测(明确不做) |
| Windows exe 版本资源 | 前端侧已解决;exe 自身仍无版本资源,属 zig/打包侧 | 已实测 |
| 英文文案润色 | 翻译以准确为先,可再按母语习惯打磨 | — |

## 明确不做

| 项 | 原因 |
|----|------|
| 用户对局出 VCF 题 | 实测 11 局 283 个局面(两档强度),可出题的漏招 **0** —— 能走 VCF 时要么已被 win1 覆盖、要么走的人自己就找到了。成本不是问题,产出才是。要做须先拿真实用户棋谱验证产出率 |
| 计时对局 | 横切面大,仍无明确需求 |
| 禁手规则(Renju) | 动 core + 双引擎,需先 spike |
| 联机对战 | 超出纯前端 + zig 壳量级 |
| Linux 打包 / 自动更新 | 平台侧,自动更新与联网决策绑定 |

## 验收口径

- 单测全绿(含 i18n 四道闸、worker bundle 闸、版本号闸、对称变化闸、复盘曲线闸、备份闸);
  交叉回归 10/10;每日/练习 8/8;强度基线不变。
- 涉及文案的改动:英文态全控件命中/溢出审计必须干净。
- 引擎类改动:`scripts/arena.mjs` 相对上一个发布 tag 净分不为负,且换一档预算复现。
  (v1.31 的对称变化按构造就是零代价,实测净 0。)
- 题库类改动:`打开练习` 延迟必须留在百毫秒量级(v1.27 从 3.3s 压到 66ms,不可回退)。
