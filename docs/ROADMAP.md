# Goban 路线图 — v1.34.0(本版) · 后续评估

> 评估基准:v1.32.0(键盘可达 / 浅色主题达 AA / 尺度收敛 / 侧栏免滚动)。
> 已具备:C1/C2 双引擎、复盘 3.0、swap2 平衡开局、战术练习(三题型 + 错题本)、
> 每日挑战、对局统计、四套棋盘主题、SGF 全链路、多存档槽、中英双语、
> macOS/Windows 双平台发布。

## v1.34.0 · 本版内容

设置面板的三处自相矛盾。

- **脚栏原本是嵌在磨砂面板里的一块实心板**(v1.33.0 我造成的):侧栏是 `--panel` 94% + 
  `blur(22px)`,脚栏却是实心 `--panel`、无模糊、宽 243 对 284。改法不是给它配一层更像面板的
  背景——试过 94% 半透明(木色主题下能读出条底下滚过的「导入」)、试过 98%(遮症状不是修)——
  而是**结构解决**:侧栏不再滚动,内部新增 `.side-scroll`,脚栏是它的兄弟节点,内容物理上到不了
  脚栏下方,脚栏因此不需要任何背景(实测 `rgba(0,0,0,0)`)。闸门 Q 守这个不变式。
- **「主题」是唯一没有胶囊底的分段控件**(v1.9.1 起的例外),统一为 `.pill`。注意色板按钮带
  `data-theme`,会在自身重新声明该主题变量,`.pill` 里任何取自变量的颜色都必须有 `--sw-*`
  对应物,否则重演 v1.32 修过的 2.87:1。
- 清掉已无使用者的 `.setting-row.stack`。

### 量过但不做:控件左边缘对齐

右边缘齐在 20px,左边缘有 7 个位置。统一到一列需要:中文 230px(可用 243 ✓)、
**英文 300px(可用 243 ✗)**。英文 `Level: Easy/Normal/Hard/Max` 现在能放下正是靠「短标签 +
右对齐」(35+12+197=244,已顶边)。要拉齐只能缩窄控件或加宽侧栏,属另一个量级。

## v1.33.2 · 上一版内容

- **「新局」主按钮的白字在日间/笔记本主题下不达标**。12px/600 适用 4.5:1,实测文字所在的
  整条带只有 3.44–4.20(按钮顶边 2.79)。同色系压深到 `#4477a8 → #2b5580`,最差点 4.72。
  这条渐变自 **v1.9** 就在,躲过四次审计的原因是**我的探针一直把渐变背景整个跳过**——
  v1.32/v1.33 说的「四主题对比度审计干净」应更准确地表述为「在我检查过的元素里干净」。
  新增闸门 P:渐变背景上的文字按色标插值逐点算。顺带补测顶栏(`.chrome` 同为渐变,同样一直
  被跳过):四主题下 4.88–15.76,全部达标,无需改动。

复查未退化:sticky 脚栏不遮挡滚到底的内容(遮 0px、点击命中)、连按悔棋收敛、复盘视角悔棋
按钮禁用、中断后「复盘分析」仍出结论且引擎继续应手。

## v1.33.1 · 上一版内容

对 v1.31–v1.33 的改动做了一次「功能还在不在」的回顾,找到两处倒退,都是自己造成的。

- **悔棋能把棋局永久卡死**(v1.33.0 引入)。中断被放在 `undo()` 的守卫之前,于是执白开局时
  电脑在空盘思考(aiThinking 真、history 空),按 `z` 会掐掉思考然后 early-return:没人调
  `maybeAiTurn()`,电脑再不落子;没人调 `sync()`,状态永远冻在「电脑思考中…」。按钮在该状态
  是禁用的,但 `z` / `⌘Z` / 原生菜单三条路径直达 `undo()`。改法:守卫回到最前。闸门 O 用探针
  在「思考中且 0 手」的瞬间派发 `z`,不靠时序。
- **拖放导入 .sgf 没人再告诉你**(v1.32.0 引入)。功能从未动过(`Host.onDropFiles`),但 v1.32
  做侧栏减法时删掉了全应用唯一提到它的那句提示。写回说明弹层(参考信息属于说明,不该长期占
  界面),并删掉两条确已无用的文案。新增单测闸门:**每条词条都必须被引用**——死文案往往就是
  某个能力失去最后一扇门的指纹。

复查确认未坏:五个脚栏入口、`清除存档`、侧栏四种关闭方式、减少动效下的弹层与棋盘、棋谱四个
操作的禁用逻辑。

## v1.33.0 · 上一版内容

四项都是界面上量得出来的缺陷,没有新功能。

- **打开应用只看得见 5 个按钮**。侧栏默认关闭,练习/每日/统计/存档/复盘 五个入口全在 ☰ 之后,
  且无任何首启引导。v1.32 优化的是"侧栏打开之后不用滚",落在了用户还没走到的地方。
  改法:首次运行展开一次(仅窗口宽 ≥900px,更窄时侧栏是盖住棋盘的浮层),之后记住用户的选择;
  并把脚栏**钉住**——v1.32 刮到 856px 只解决了 900 高这一个窗口,**1280×720 下五个入口又掉到
  线下**。sticky 之后 600/720/768/900 各高度实测 5/5 可见。入口按一条规则重排:
  打开面板的进脚栏,直接作用于本局的(复制/导出/导入/粘贴)留在「棋谱」区。
- **极限档每手 5 秒(深 8 秒)没有出口**。期间悔棋与提示禁用,状态只有静态的「电脑思考中…」。
  慢是引擎的正常代价,问题是不可中断。改法:悔棋在思考期间保持可点,点了即中断并撤回自己那一手
  (`gameGen` 加一 + 重启 worker);超过 1 秒状态栏开始计秒。中断后引擎照常工作(实测再落一子
  正常应手,5012ms)。
- **`prefers-reduced-motion` 只有一条规则**(`.think-dot`),开启后仍有 57 个元素在动。
  补成真正的媒体查询块,实测 57 → 0,正常态 58 个动效不变。过渡压到 0.01ms 而非删除,
  `transitionend` 仍会触发。
- **复盘曲线 canvas 无文字替代**。补 `role="img"` 与说明,接到下方本就是文字的失着列表。

### 评估后撤回的一项

原计划把 **难度 × 思考** 并成一条单调档位(理由:困难·深 3500ms > 极限·快 2500ms,时间阶梯
交叉)。实测撤回——前提"棋力是时间的单调函数"不成立:极限不只给更多时间,还改搜索档
(`vctDepth` 8→10、`maxDepth` 12→14)。两轮各 8 个真正进入搜索的局面,**每加一档时间约
2–3/8 的着法改变**,这个旋钮在做事。

## v1.32.0 · 上一版内容

四项都是界面上量得出来的缺陷,没有新功能。

- **Tab 走不到任何按钮**。Tab 早年被绑去开合侧栏,于是主界面 38 个可见按钮虽然全部
  `tabIndex >= 0`,键盘一个都到不了——而弹层从 v1.25.2 起就有完整焦点陷阱,守着一个进不去的
  房间。侧栏另有三种开合方式,Tab 还回去:侧栏可达 **0 → 26** 项,弹层逃逸仍为 0。
- **浅色主题达不到 4.5:1**。日间 `--muted` 3.79、笔记本 3.86;更糟的是 `--accent` 是按「面」
  调的(描边/色块/落子标记),却有五处直接当文字用,日间的棋谱四个链接只有 **2.75:1**。
  分出 `--accent-text`,深色主题沿用 `--accent`(实测 8.06/8.57),仅日间压深到同色系
  `#8c6026`(4.88:1)。
- **尺度收敛**。按实际渲染值统计:字号 8 → 4、字重 4 → 3、圆角 7 → 4 级、间隙 7 → 4;
  内边距 18 → 9,承担 226 处的 5 个主值全在 4px 网格上。
- **侧栏做减法**。五个功能入口原本要滚一下才看得见(内容 1002px / 窗口 900px)。没有加徽标或
  往顶栏塞按钮,而是删常驻提示段落与多余的 `收起` 按钮、`清除存档` 并入存档弹层:
  **1002 → 856px**,960×900 与 1440×900 下五个入口全部免滚动。

另加 `role="status"` 三处播报,以及一条新闸门(见下)。

### 自伤与闸门

删 `收起` 按钮时留下了无守卫的 `getElementById("collapse").onclick`,它在**初始化中**抛错,
其后所有事件绑定全部没绑上——界面照画,看着正常,只是什么都不响应。交叉回归的
`page.__errors` 断言跑一次就抓得到,但这类错误值得更早更便宜地点名:单测新增闸门,
`src/web/js/` 中任何无守卫的 `getElementById("x").`,`x` 必须存在于 `index.html`。

交叉回归新增三条界面闸门(对比度含透明度合成 / Tab 可达性 / 折叠线),三条都做过反证。

## v1.31.0 · 上一版内容

三项都是已发布功能的实测缺陷,不是新功能。

- **电脑不再每盘下同一局**。同一开局重复 8 局,困难档只走出 1 盘棋(普通 3 盘);
  真机预算下同一局面连测 5 次应手逐字相同。改法不是「在分数接近的着法里挑」——那是拿棋力
  换花样——而是**用局面已有的对称性**取等价着法:棋盘翻转后局面不变,翻转后的应手就是同一手
  棋换个镜像坐标。困难 1 → 5 盘不同,普通 3 → 6;arena 对 v1.30.0 净 0,强度基线不变。
- **复盘曲线原本是贴顶的平线**。`tanh(raw/1200)` 在第 7 手就恒等 1.000000,91 手里 90 手的
  逐手跌幅恰好为 0;失着判据一次都没触发,每局只报「输掉的那一手」。曲线改对数压缩(活三读
  0.60 而非 0.97),判据改为「对手应手之后」再比。每局失着 1 → 平均 4.5 处,首个比终局提前
  中位 21 手,上限 8 处。
- **全部数据可备份**。六个存储键一次导出为 JSON,恢复前校验 + 确认,整体替换。此前只有棋谱
  导出(一次一局),统计/打卡/练习进度完全没有出口。

## 后续候选(未排期)

| 项 | 说明 | 证据 |
|----|------|------|
| 变化性再往前 | 对称性只在局面对称时有轨道,通常是开局几手。再往后要变化就得动「接近最优」,那是真实棋力代价,需先用 arena 定价 | 已实测 |
| 失着判据 | 现为静态评估跌幅 + 两条硬判据。更准的转折点(允许对手成活四/双三)需要新的判据并重新定阈值;我试过的 VCF 判据在样本里 0 命中 | 已实测 |
| vcf 题量 | 扩开局集后仍是最难产的类型;再往上需要换采集策略 | 已实测 |
| 练习难度分级 | vcf 有真实梯度(深度 3–8);win1/defend 的解数几乎全是 1,分级会沦为按子数排序 | 已实测 130 题全量 |
| 棋盘键盘可操作 | canvas 无 tabindex、不在 Tab 环内,三条键盘路径均无法落子。v1.32 让 Tab 走得到所有按钮,但棋盘落子仍需一整套光标状态 | 已实测(明确不做) |
| 每日未完成提示点 | 侧栏「每日」旁一个小圆点。v1.33 已让入口在任何窗口高度都钉住可见,提示点的边际价值需再看 | — |
| 困难·深 是被支配的格子 | 3500ms,落子与 极限·快(2500ms)有 6–7/8 相同,难度档还更低。删格子或重调预算都动引擎,需先用 arena 在真实墙钟预算下定价 | 已实测(两轮 × 8 局面) |
| 棋盘 DPR 上限 | 现封顶 2×。3× 重建实测 74.2ms(2× 为 33.5ms),要放开需先拆静态层(棋盘格与木纹同棋子分开缓存) | 已实测 |
| Windows exe 版本资源 | 前端侧已解决;exe 自身仍无版本资源,属 zig/打包侧 | 已实测 |
| 英文文案润色 | 翻译以准确为先,可再按母语习惯打磨 | — |

## 明确不做

| 项 | 原因 |
|----|------|
| 用户对局出 VCF 题 | 实测 11 局 283 个局面(两档强度),可出题的漏招 **0** —— 能走 VCF 时要么已被 win1 覆盖、要么走的人自己就找到了。成本不是问题,产出才是。要做须先拿真实用户棋谱验证产出率 |
| 计时对局 | 横切面大,仍无明确需求 |
| 禁手规则(Renju) | 动 core + 双引擎,需先 spike |
| 联机对战 | 超出纯前端 + zig 壳量级 |
| Linux 打包 / 自动更新 | 平台侧,自动更新与联网决策绑定 |
