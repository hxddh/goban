# Goban 路线图 — v1.25.0

> 评估基准:v1.24.0(战术练习 + 对局统计 + 代码模块化)。
> 已具备:C1/C2 双引擎、复盘 3.0(评分曲线/失着/推演/评注 SGF)、swap2 平衡开局、
> 战术练习、对局统计、四套棋盘主题、SGF 全链路、多存档槽、macOS/Windows 双平台发布。
>
> **本版约束(定版原则):不大幅增加复杂度,不引入不可控内容。**
> 依据本仓库自身的历史:回归风险集中在引擎与对局主流程
> (v1.19.2–v1.20.0 连续五版修引擎相关问题;v1.23.1 整版做交叉场景硬化)。
> 因此本版只做**纯增量、与对局状态零接触**的内容,不碰 core 规则层、
> 不碰两个 AI 引擎、不碰对局主流程。

## v1.25.0 内容

### P0 · 品牌刷新:新 logo(已完成)
- 新图标:木纹棋盘 + 黑子斜线连珠(胜形)+ 两枚白子,呼应应用内「原木」主题配色。
- 矢量源 `assets/icon.svg` 入库,`assets/icon.png`(1024×1024)由其渲染,后续改版只改 SVG。
- 风险:零(纯资源替换,不触碰任何代码路径)。

### P1 · 每日挑战
- 基于现有 practice.js:每天以日期为种子,从题库(内置题 + 自身对局生成题)中
  确定性选出一组 5 题;当天重进结果一致。
- 完成度与连续打卡天数进统计面板(独立存储键,不混入胜负统计)。
- **实现边界(控制复杂度的关键)**:
  - 只复用 practice.js 已有的两类题型与判定逻辑,**不新增题型**;
  - 独立弹窗与小棋盘(与「练习」同一套),与对局状态零接触;
  - 不改 core.js / ai.js / ai2.js / app.js 对局流程,新代码集中在
    practice.js 扩展 + stats.js 展示一小块;
  - 无网络、无新依赖、无平台侧改动。
- 风险:低(与 v1.24.0 的练习/统计同一模式,该模式已被验证)。

## 明确移出本版(附原因)

| 项 | 原因 |
|----|------|
| 计时对局 | 横切面大:时钟 × 悔棋 × 存档 × 导入 × swap2 × AI 预算,正是 v1.23.1 花整版清理的那类交叉场景。值得做,但应作为 1.26 的主菜单独做、单独回归 |
| 禁手规则(Renju) | 本仓库最不可控的改动:动 core 规则层 + 两个引擎的胜形判定,引擎强度回归风险最高。排期前需先做引擎侧可行性 spike(禁手分支对搜索/棋型评估的影响面),再决定是否立项 |
| 联机对战 | 需要服务端/信令,超出「纯前端 + zig 壳」架构一个量级,单独立项评估 |
| 英文界面 i18n | 值得做,但应在 UI 稳定后一次性抽取文案 |
| 开局库浏览器 | 受众窄,先看 swap2 使用反馈 |
| Linux 打包 / 自动更新 | 平台侧改动,与本版约束冲突,后续打包侧改动时一并评估 |

## 验收口径

- 单测全绿(`scripts/test-game.mjs`);每日挑战选题的确定性(同日同题)入单测。
- 浏览器冒烟:每日挑战完整答题流(答对/答错/整轮完成/打卡累计)、
  与练习/统计弹窗互不干扰、0 控制台报错。
- 对局主流程零改动 → 无需引擎强度回归(`test-strength.mjs` 基线不变)。
