## v1.46.0 · 本版内容

两件事形状相同:**修正的意图早就在代码里了,只是从来没生效过**。

- **英文界面里坐着两个中文按钮**。存档列表每行的「读取」「删除」在英文界面下原样是中文
  (实测:界面 lang=en、存档名正确地是 `Game 08-04 00:34`、按钮却是「读取」「删除」;
  存档默认名**是对的**,我一度以为它也漏了,那是探针先建档后切语言 —— 撤回)。根因是
  `slots.js` 用 `innerHTML` 拼了字面量,没走 `t()`;改成 `createElement` + `textContent`。
  **而防这件事的闸门没响**:它的正则只认双引号,这两行是单引号 —— 同样的内容,
  `'">读取</button>'` 漏、`">读取</button>"` 命中。闸门改成三种引号都认,并把这四条自检
  写进闸门自己。**一改宽就抓出第三处** `practice.js:485`,但那是**注释**
  (`/** 'free' (练习) or 'daily' (每日挑战) */`) —— 旧的剥注释只处理 `//` 和以 `*` 开头的
  行,漏了单行块注释。**这是本仓库第四次把散文当实现**,所以修的是剥注释器:新的
  `stripComments()` 感知字符串、跨行处理 `/* */`、保留行号,自带四条自检。
- **统计表其实被帮助弹层的快捷键表接管了**。数字格右对齐、表头不是,每个数字表头都坐在
  它所标注那列数字的**左边 18–32px**(中文 +23/+23.1/+23/+29.9,英文
  +20.6/+18.1/+19.1/+31.7)。而样式表里早就写着
  `.stats-table td.num, .stats-table th.num { text-align: right }` —— 运行时 `th.num`
  **命中 0 个**、`td.num` 命中 16 个:表头是 i18n 里一整条 HTML 串,没人给它 class。
  补上 class 之后**还差齐整的 8px**,根因更深:`.modal td { padding: 8px 0 }` 与
  `.stats-table th, .stats-table td { padding: 4px 8px }` **特异度相同**(0,1,1),写在后面
  的赢;而那套规则是给帮助弹层的「按键 → 说明」表写的,统计表只是碰巧也住在弹层里,于是连
  `.modal td:first-child { width: 42% }`(按键列的宽)、强调色、等宽 12px 一起继承了。
  按来源收窄:帮助表拿到自己的 `.keys-table`。改后数字表头右缘差 **0**、th/td 内边距都是
  `4px 8px`、行高 26/26.5(原 26/37.8)、难度列 79.7px(原 142px=42%)。
  **帮助表逐项没动**(142px/42% · --accent-text · SF Mono · 12px · padding 8px 0 · 13 行 ·
  弹层高 732px),改名对它是等价的。

## v1.45.1 · 上一版内容

**前端一行未动**(只有版本号)。补上 v1.45.0 没发出来的 Windows 安装包。

- **Windows 构建在链接期就红了**:`lld-link: undefined symbol: createWindowsGpuRenderer()`。
  逐版本核过 npm 上的 SDK:0.6.3 / 0.7.0 / 0.7.1 既没有 `gpu_surface_renderer.cpp`
  也没有这处引用,**0.7.2** 和 0.8.0 两样都有 —— SDK 0.7.2 把一个 Direct2D 合成器拆成了
  独立源文件并让 `webview2_host.cpp` 调它,而本仓库 `build.zig`(是 SDK `build/app.zig`
  的一份分叉,早就漂了)Windows 那一支**始终只编 `webview2_host.cpp` 一个源文件**。
  **不是 v1.45.0 的代码引起的**:v1.44.0 是 7 月 29 日建的,那时装到的还是 ≤0.7.1,
  同一份 v1.44 今天重建也会红。这是环境漂移,只是被那次发布先撞上。
- **改法**:SDK 不锁版本是有意的,所以 `build.zig` 得扛得住它遇到的那一版 ——
  `addWindowsGpuRenderer()` **先查文件在不在**再编(无条件加会把断裂搬到 ≤0.7.1 上去),
  三个分支(webview2 带层 / webview2 桩 / cef)都接上,与 SDK 自己的 `build/app.zig` 一致;
  另补 `d2d1` / `dwrite` 两个系统库,SDK 的规范链接列表里有、我们这份漏了。

### 我自己踩的一个坑

第一版写成 `std.fs.cwd().access(path, .{})` —— 那是 Zig 0.15 的拼法,0.16 直接编译错误
(`root source file struct 'fs' has no member named 'cwd'`)。0.16 是
`std.Io.Dir.cwd().access(io, path, .{})`,`io` 取自 `b.graph.io`,本仓库 `build.zig` 里
`std.process.run` 早就在这么传了。

### 两条真机结论

同一工作流同一分支跑了三次,前两次红 —— 这三次本身就是反证链:`6fcb418` 红(SDK 那个
链接错误)、`85715fe` 红(我的 0.15 拼法)、`4152531` **绿**(`zig build` 3m10s,
`Goban-Windows-x64` 1,711,205 B)。

**「链接过了」不等于「跑得起来」**:二进制里多了一个 Direct2D 合成器,所以又跑了一遍
`smoke-windows`(15 步全绿):窗口 960×749、`surface.resize scale=1`、
`runtime.frame frame=1 dirty_regions=2`(真的出了帧)、三次 `bridge.dispatch` 往返、
桥白名单拒绝未登记命令、无静默错误。

## v1.45.0

三件事,前两件是「界面在报一个它自己算错的数」,第三件是打开侧栏第一眼的那块参差。

- **每一局的用时都记成 0**。实测同一条落子路径、第一手之后等 10 秒再连五:v1.44 钟停在
  `00:00`、`durationMs` **0**、累计时长 **0**;v1.45 是 `00:10` / **10377** / **10377**。
  统计面板「共 N 局 · M 手 · X 小时」里的小时数读的正是这个累加值 —— **这一项从有它
  那天起就一直是 0**。原因在赋值顺序:`nowElapsed()` 在终局之后直接返回 `elapsedBaseMs`,
  而两处终局分支都是先置 `result` 再读用时。改成先结算 `elapsedBaseMs = nowElapsed()`
  再翻标记;连五与和棋**是同一个错**,都改了。
- **「清空」按钮又活过来了**。「做过每日挑战、一局都没下完」这个常见状态下,v1.44 里
  按钮可点、点得下去、确认得了,然后正文 33 个字符**一个都没变** —— `clear()` 根本不碰
  每日打卡。v1.39 修过一次「零对局时照样可点」,判据却写成 `hasAny`(= 有对局 **或** 有
  每日打卡),被打卡数据重新点亮。判据改成跟对局数走。
- **设置区六个控件、六个左边缘**。v1.44 实测(相对行左缘):中文 77/93/126/141/148/157,
  英文 46/57/96/122/144/148;宽度同样六种(中文 86–166、英文 95–197)。控件右对齐、自然
  宽度,于是右边缘齐、**左边缘参差**,而人眼扫的正是左缘。v1.34 量过并留在路线图,当时
  结论是「英文要 300px」就搁置了 —— 前提站不住:余量在控件自己身上。格子内边距
  `12px → 5px`(文字一个没少,Level 197 → 161)、主题四个字**改成四块色板**(自然宽
  186 → 46,且与语言无关)。设置行改成「标签列 + 控件列」,列宽是 token `--ctl-w: 161px`
  (英文最宽控件的自然宽)。改后中英**都是**左边缘 1 个位置、宽度 1 种(161)。
- **焦点此前完全由引擎默认值决定**。整张样式表唯一一条 focus 规则是 `.slot-name:focus`。
  实测 Chromium 给的是 `rgb(16, 16, 16) auto 1px`、offset `0px` —— 一条贴死在控件上的
  近黑细线。v1.32 花一整版把 Tab 可达做起来(侧栏 0 → 26 项),却没定义过「走到哪儿」看
  不看得出来;而这个应用跑 WKWebView / WebView2、回归跑 Chromium,**靠默认值撑住要紧的
  东西正是 v1.38 修掉的那类依赖**。现在应用自己画 `:focus-visible`。主题色板有个坑:
  `[data-theme]` 按钮内部重新声明了被预览主题的调色板(v1.32/v1.34 踩过),用 `--sw-accent`
  在进色板之前把当前主题的强调色捞出来。

### 一条用户下的硬约束,以及它否掉的方案

先试的是「标签在上、控件在下」的堆叠版:对齐同样干净、代码更简单。**否了** —— 900 高的

横排版最终反而比 v1.44 **小 2–3px**(中文 740 → 737、英文 758 → 756),600/720/749/900
四个高度上要不要滚的结论与 v1.44 **逐格相同**。

### 得说清的代价

主题标签不再显示在屏幕上。名字只是**视觉上**藏起来(`font-size: 0`),文本节点与 `title`
都在 —— 实测无障碍名中文「木/夜/日/本」、英文「Wood/Night/Day/Paper」,悬停有完整 title。

### 评估里列过但没做

**顶栏和侧栏都显示手数+时钟**。确是重复,但两处用途不同(一处随时可见、一处在侧栏语境

### 新增闸门(均反证过)

单测:终局赋值顺序(反证把 `elapsedBaseMs = nowElapsed()` 挪回 `result` 之后,两处都报红)·
「清空」的判据必须是局数而非 `hasAny`。
交叉 **AD**:设置行控件左右边缘中英各只有一条,且**宽度跨语言相同**(反证拿掉那个 token,
报出中文 5 个 / 英文 6 个左边缘)。**AE**:`:focus-visible` 规则存在且每个受测控件都拿到
非 none、非 0 宽的描边与非 0 offset。**AF**(新):四块色板互不相同、选中态唯一、名字只是
视觉上藏起来。

**写闸门时踩的两个坑**:一、第一个反证打在了**不承重**的那条规则上 ——
`.setting-row > .pill { justify-self: stretch; width: 100% }` 改掉闸门照样绿,因为 `.pill`
自己就有 `width: 100%`,那一整条是冗余的(已删,留着会让人以为是它在起作用);承重的是

另外 AF 的第一个反证也没打响:只删 HTML 里的按钮文本不够,`data-i18n` 会在运行时填回来,
得连 `data-i18n` 一起删。

## v1.44.0

两处同一形状:存储有上限(这没错),但到了上限之后界面继续显示得像没事一样。

- **「最佳连胜」会倒退**。面板上每个数字都从那份**上限 200 条**的对局列表现算。实测
  12 连胜 → 再输 200 局,最佳连胜读出 12 → 12 → **0**(那 12 局被挤出存储)。同一条
  上限还让「共 N 局」卡在 200、总手数卡在 10000(实际 212 局 × 50 = 10600)、当前连胜
  被截断(250 连胜显示 200)。而分难度胜负表与总计行都没有「最近 200 局」的字样。
  隔壁 `practice.js` 的每日打卡 `bestStreak` 一直是累计存的 —— 统计是唯一的例外。
  改法不是把 200 调大,是把两件事分开:`goban.v12.totals` 存累计量(只有 record /
  unrecord 会动,永不重算,面板只读它),`goban.v12.stats` 那 200 条明细退回幕后,
  只用于悔棋撤回匹配 `endedAt` 与首次播种。改后 212 局 / 最佳 12 / 10600 手。
  悔棋撤回会把局数、手数、当前连胜、分难度胜场都减回去;**最佳连胜不下调**——它是
  高水位,一个随撤回抖动的记录正是本版要修的毛病。
- **存第 31 个存档,静默删掉第 1 个**。`add()` 是 unshift、`persist()` 是
  `slice(0,30)`:列表仍 30 条、最老的从「第1个」变成「第2个」、`add()` 返回 true、
  toast 照说「已保存」。这些是用户亲手命名的存档,而清除存档和恢复备份都要确认。
  现在满槽再存先问,并**指名**将被丢掉的那一个;点取消实测 30 条一个不少。

### 新增闸门(均反证过)

单测:累计量在明细被截断后不倒退(反证内嵌 —— 拿 v1.43 那套「从列表现算」跑同一份

## v1.43.0

- **每一份导出的棋谱都写着「对手认输」**。SGF 的 `RE` 第二段是赢法(`+R`=Resign、
  `+T`=超时、`+F`=判负),而 `sgf.js` 把 `result==="b"` 硬编码成 `"B+R"` —— 这个应用
  **没有认输功能**(全 src/ 搜 resign/认输,0 处命中),赢棋只有连五一种。为什么一直没
  发现:**解析器不读 RE**,结果从盘面重算,自己导入自己毫无异样;这个字段唯一的读者在
  应用之外,也因此从没有任何测试碰过。改为 `B+` / `W+`。
- **一半的动效没在用这个应用的曲线**。运行时 130 个过渡属性实例:时长 **6 种**、
  缓动 **2 条**(自定义 63 次 vs **浏览器默认 ease 67 次**),**18 个元素在同一条规则里
  混用两条** —— 顶栏按钮的 background/transform 走自定义而 opacity 漏写曲线落回默认;
  `#board-wrap` 的 width/height 走 .28s 自定义而 background/box-shadow 走 .25s 默认。
  两条曲线逐点最大差 **37.9 个百分点**(在时长的 20% 处):按钮 150ms 反馈里第 30ms
  位移完成 67%、淡入才 30%。收敛后时长 **3 档**、过渡缓动 **130/130 一条**、混用 **0**。
- **曲线按角色分两条,这是规则不是例外**:`--ease` 一次性过渡(起步快收尾稳)、
  `--ease-loop` 循环脉动(两端对称,接得上环 —— 强 ease-out 循环起来接缝处会顿)。
- **两个思考指示器错拍**:同时在屏上(显示条件都是 `aiThinking && result==="play"`),
  却跑 1.2s 与 1.1s,最小公倍数 **13.2 秒**才对齐一次。现在同周期同曲线。
  **这一条会改变手感**,是有意的:原本跑默认曲线的那 52% 会变成起步更快的收尾曲线。

### 扫过但清白(免得算成没查)

## 这套回归能证明什么,不能证明什么

v1.38 之前,这份路线图和历次发布说明里的像素数字都被当成「关于发布版应用」的事实在陈述。
它们不是。两条边界必须记在这里,因为它们不会自己浮出来:

**引擎不同。** 交叉回归跑在 Playwright + Chromium;应用在 macOS 跑 WKWebView、在 Windows
跑 WebView2。**canvas 2D 的几何与合成是规范定义的**(棋子半径、格距、alpha 叠加、对比度算术),
那部分结论跨引擎成立。**UA 默认样式、焦点环、滚动条、以及任何「某个 CSS 特性存在与否」的
问题,这套回归结构上看不见** —— color-mix 那 37 处缺兜底能躺 28 个版本,就是这个盲区。

**字体不同。** 容器里渲染中文落到 **WenQuanYi Zen Hei**(闸门 X 钉住了这一点),而 macOS 装
苹方、Windows 装微软雅黑,两个平台都没有它。所以**任何文字的绝对像素值 —— 换行数、元素高度、
弹层高度 —— 只是那个字体下的读数**,不是对发布版的断言。跨字体成立的是「有余量」这类性质,
闸门 W 把字号推到 125% 去证它。
